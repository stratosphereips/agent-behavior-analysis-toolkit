How the fingerprint decides a verdict

Each run is classified top-down. Behavior gates learning (rule 1); among learners, the return↔coverage relationship separates the modes. Every branch is a significance test against a calibrated null or a calibrated effect size — no hand-set thresholds.

What each test actually is

Every diamond resolves to one calibrated test at α = 0.05.

Activity above null?

Is the count of active checkpoint-pairs greater than a non-learning policy would produce?binomial test vs P₀ = 5%

Return trending up?

Does mean return rise over training, beyond its own variance?regression-slope test

Coverage collapses?

Perplexity trends down and the net drop exceeds coverage's own oscillation scale.slope test + calibrated effect size

Tail still active?

Is the last quarter of training still firing above the null rate?binomial test on the tail

Activity winding down?

Is the tail fire-rate significantly below the early-training rate?two-proportion test (head vs tail)

A single per-pair “active”

A change above the calibrated noise floor and above the practical floor εmin.z > zₓₖₕ AND raw > εmin

Why the tree is shaped this way

Three principles are baked into the branch order.

1

Behavior gates learning. Rule 1 decides learner-or-not from activity alone. A run at the null floor is “No learning” no matter what its return does — which is what stops a random policy’s drifting return from being mistaken for gaming.

2

Return enters only among learners. Once behavior confirms real change, the return↔coverage relationship separates the modes: return up + coverage collapse = gaming; return up + no collapse = good; active without return gain = reshaping.

3

Every threshold is calibrated. Each branch is a significance test against the calibrated null, or an effect size measured against the data’s own noise (εmin for activity, perplexity’s oscillation for coverage). No bare magnitude cutoffs remain.
